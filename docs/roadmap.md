# Corpus 路线图

**一条硬规则贯穿全程**：每个里程碑结束时，必须能在 **30 分钟内从头跑到"能用"**。做不到就说明这一步切太大了。这是防止项目在第 4 个月死掉的唯一有效手段。

**每个里程碑收尾时**：在 `docs/journal/NN-<里程碑>.md` 记 15 分钟的**坑**——只记具体问题和最后的做法，不写教程。格式见 `AGENTS.md §6`。

估算单位：人日，已含调试和返工，不含学习成本。

---

## 里程碑总览

| # | 里程碑 | 人日 | 结束时能做什么 | 验收标准 |
|---|---|---|---|---|
| M0 | 骨架 + 裸流式对话 | 4~6 | 在终端或最小页面里和 LLM 对话，逐字显示 | 能中断生成；断了能重发 |
| M1 | **契约定义**（只写类型） | 2~3 | `tsc` 通过，什么都还跑不起来 | `Document`/`Chunk`/`Locator`/`Citation`/`Host`/`RenderDescriptor` 全部定稿 |
| M2 | 文件入库 + Markdown 解析 + 索引 | 7~10 | 拖一个 .md 进去，能看到文件列表和分块数 | `embedding_model`/`embedding_dim` 已落库 |
| M3 | 混合检索 | 5~7 | 命令行 `corpus search "..."` 能查到刚上传的内容 | 向量与 BM25 都能单独跑通、再合并 |
| M4 | **RAG 回答 + 引用 + 拒答** | 7~10 | 提问得到带出处的答案；问资料里没有的会明说不知道 | **项目核心验收点** |
| M5 | 聊天 UI 完整化 | 8~12 | 能日常使用：流式、引用可点开、文件管理、多会话 | 连续用 3 天不觉得别扭 |
| M6 | PDF 解析 | 8~12 | 能导入 PDF，引用能跳到具体页 | **插件接口验收**：加 parser 不改核心一行代码 |
| M7 | **评测体系** | 2~3 | 一条命令跑 30 条问答，打印命中率 | 每次改动前后能对比 |
| M8 | 联网检索 | 5~7 | 答案里能带网页链接和抓取片段 | 断网时优雅降级 |
| M9 | MCP 接入 | 8~12 | 装一个 MDN MCP，问 CSS 新特性答得准 | **插件协议验收**：跑通 3 个真实插件 |
| M10 | 对话即摄取 + 信任分级 | 5~8 | 一键"存为知识"，能从历史里检索到 | `model` 来源不出现在引用栏 |
| M11 | Tauri 壳 + 打包 | 6~10 | 双击安装，能开机自启、单实例 | 实体机全新安装能跑 |

**合计：约 68~100 人日。** 全职 3~5 个月，业余（每周 10 小时）约 6~8 个月。

## 阶段划分

```
阶段一：能跑通一条链（M0~M4）      约 25~36 人日
  → 交付：一个可以问自己资料的 CLI

阶段二：能用（M5~M6）               约 16~24 人日
  → 交付：一个可以日常使用的网页应用

阶段三：可信（M7~M8）               约 9~12 人日
  → 交付：质量有标尺、来源更广

阶段四：可扩展（M9~M10）            约 13~20 人日
  → 交付：插件体系成立、知识会生长

阶段五：可分发（M11）               约 6~10 人日
  → 交付：一个能装的应用
```

**注意**：阶段一结束时项目就已经有价值了（能查自己的笔记）。后面的每一阶段都是增量，不是"必须全做完才有用"。

## M4 的详细验收（项目的命门）

M4 做对，后面都是加法；M4 做错，后面全是补丁。

### 必须能通过的对话

```
✅ 有答案的提问
   Q: "我在 README 里写的技术栈是什么？"
   → 答案 + 引用（显示 README.md 的技术栈表格）

✅ 需要串联的提问
   Q: "为什么我们选了 SQLite 而不是 Postgres？"
   → 答案 + 引用（找到 docs/architecture.md 的决策记录段落）

✅ 资料里没有的提问
   Q: "这个项目的 CI 配置是什么？"
   → "资料里没有提到 CI 配置。"   ← 绝不可以用常识编一个

✅ 与资料无关的提问
   Q: "今天天气怎么样？"
   → 明确说明不在资料范围内
```

**任何一条失败，M4 就不算完成。**

### 引用的最低要求

- 每条答案至少一条引用
- 引用能显示：文档标题 + 原文片段
- 点击能打开原文并定位（Markdown 定位到行/标题，PDF 定位到页）
- 引用里的片段必须是**原文逐字**，不是模型改写

## M7 评测方案（2 人日的最小版本）

**不是测试体系，是一把尺子。** 不做覆盖率、不做 CI、不做 E2E。

```
evals/
├─ cases.json       # 30 条
└─ run.ts           # 跑完打印三个数
```

```jsonc
// cases.json 的一条
{
  "id": "q01",
  "question": "为什么选 SQLite 而不是 Postgres？",
  "expectDocs": ["architecture.md"],        // 期望召回哪份文档
  "expectKeywords": ["单文件", "零安装"],    // 答案里必须出现
  "expectRefusal": false                     // 是否应当拒答
}
```

```
$ corpus eval

召回命中率    24/30  80.0%
引用正确率    22/30  73.3%
拒答正确率     8/10  80.0%
```

### 用例怎么造（30 条的比例）

| 类型 | 数量 | 作用 |
|---|---|---|
| 有明确答案的 | 12 | 基础召回 |
| 需要跨文档的 | 6 | 检索深度 |
| 资料里没有的（应拒答） | 6 | 抓幻觉 |
| 模糊/多义的 | 3 | 抓 query 改写 |
| 高价值业务方案类 | 3 | 验证你真正关心的场景 |

### 什么时候跑

**每次改动检索参数、分块策略、提示词、embedding 模型之后。** 30 秒出结果。

没有这把尺子的后果：chunk size × overlap × top-k × 混合权重 × rerank 阈值 × 拒答阈值 是组合爆炸，凭感觉调第 5 次之后就迷路。

## 核心冻结流程（v1.0 之后）

> **冻结太早比太晚更危险。** 冻结后遇到核心缺陷，只能用插件绕过，而那些扭曲的插件会长久留在架构里。
> 事实：前 3 个真实插件会暴露核心契约 80% 的漏洞。

```
v1.0  →  契约观察期（跑 3 个插件：文件浏览 / DB 可视化 / MDN）
      →  修契约（允许破坏性变更，此时只有自己的插件受影响）
      →  v1.1 正式冻结 + apiVersion 升到 1
      →  之后只增不改
```

**"冻结"的对象是 `Host` 接口和数据类型，不是数据库 schema。** schema 永远可迁移，因为插件不直连 DB。

### 冻结前必须全绿的清单

```
契约层
  □ Host 所有方法有测试
  □ 3 个真实插件跑通
  □ apiVersion 校验生效

故障注入
  □ 断网 → 本地检索仍可用
  □ API key 失效 → 明确提示，不静默
  □ 模型 500 / 超时 → 重试策略 + 用户可见
  □ 磁盘满 / DB 被锁
  □ 中途停止生成 → 无残留请求

数据边界
  □ 空库（全新安装）
  □ 500 页 PDF
  □ 单会话 200 轮
  □ 两万条 chunk 下的检索延迟

迁移
  □ 旧版本库升级成功
  □ 迁移失败能回滚到备份

安全
  □ key 不出现在任何 API 响应里
  □ 日志里 key 已脱敏
```

## 每阶段的最小验收清单（防止自欺）

每个里程碑结束时，依次问：

1. 删掉 `node_modules` 重装，还能跑起来吗？
2. 换一台干净的机器（或新用户账户），能跑起来吗？
3. 用昨天上传的文档，今天还能查到吗？
4. 断网还能用吗（本地功能部分）？
5. 我自己愿意用它吗？

**第 5 条答"不"的次数超过两次，就该停下来修体验，而不是加功能。**

## 优先级：如果时间不够，砍的顺序

从下往上砍，砍到这条线以上就是可交付的：

```
❌ 先砍   Tauri 壳（M11）→ 用命令行 / 浏览器
❌ 再砍   对话即摄取（M10）
❌ 再砍   联网检索（M8）
⚠️ 谨慎   PDF 解析（M6）→ 只留 Markdown 也能用
⚠️ 谨慎   MCP（M9）
🛑 不能砍 评测（M7）
🛑 不能砍 引用 + 拒答（M4）
🛑 不能砍 Markdown 入库 + 检索（M2~M3）
```

**理由**：砍掉 M4 或 M7，剩下的就不是一个 RAG 应用，只是一个调 API 的聊天框。
