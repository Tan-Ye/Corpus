# 检索与引用

## 检索在做什么

把用户的问题和库里的资料都变成「可比较的东西」，然后找出最接近的几段。

传统关键词检索比较的是**词**：问题里的词在哪些段落出现过。
向量检索比较的是**意思**：「怎么切分资料」和「分块策略」字面没有共同词，但向量距离很近。

## 一次完整的链路
离线：文件 → 解析 → 分块 → 向量化 → 建索引 在线：问题 → 向量化 → 检索 → 取 topK → 塞进提示词 → 生成答案


离线那半条叫入库，在线那半条叫检索。两条链路用的必须是**同一个** embedding 模型，否则向量无法比较。

## locator：为什么不能只存文本

如果 chunk 只存一段文本，回答时用户问「这句出自哪里」就答不上来。

所以每个 chunk 必须带定位信息：

- 属于哪个文件
- 在哪几个标题下面（heading path）
- 起止行号（或页码）

有了 locator，答案里就能给出「分块策略.md › 按标题切分，第 12-20 行」这样的出处，用户可以直接点回原文核对。

## 引用不只是好看

引用的真正作用是**让错误可发现**。没有出处的答案，用户只能凭感觉信或不信；有出处的答案，用户可以点开原文对照。

这也决定了引用必须是**原文逐字片段**，不能是模型改写过的句子——改写过的片段无法核对。

## 什么时候应该拒答

检索层要能回答「资料里没有」这件事，而不是把最不相关的一段硬塞给模型。

做法是给相似度设阈值：最好的结果都低于阈值，就直接回复没有找到。阈值需要按实际语料调，通常 0.2 到 0.4 之间。

拒答比答错便宜。答错一次，用户要花时间核对；拒答一次，用户换个问法就好。
