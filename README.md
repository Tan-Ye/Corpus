# Corpus

> 你的资料，一个有据可查的整体。

个人（可平滑扩展到小团队）的知识库问答应用。把散落的文档变成一个能对话、每句话都有出处的资料体。

**当前状态**：设计阶段完成，尚未开始编码。下一步是里程碑 M0。

---

## 它是什么

不是"加了上传按钮的 ChatGPT"，而是一个读过你全部资料、随时待命、但必须交出证据的助手。

三件事是它的立身之本：

| | 含义 | 为什么不可砍 |
|---|---|---|
| **引用** | 每个答案挂原文出处，可点开、可跳回原文 | 没有引用，就无法验证它有没有编 |
| **拒答** | 资料里没有就明说，不用通用知识糊 | 这一条比引用更难做，也最能区分工程水平 |
| **评测** | 30 条问答对做回归标尺 | 使用者不是用户，是**你自己**。改了参数才知道变好还是变坏 |

前两条是对用户的承诺，第三条是对自己开发时的承诺。

---

## 它做什么

| 功能 | 说明 |
|---|---|
| 对话 | 流式、多轮、可中断 |
| 联网检索 | 搜索 + 抓取 + 引用 |
| 资料入库 | 上传、解析、分块、索引 |
| 检索 | 向量 + 关键词混合（BM25），可选 rerank |
| 引用溯源 | 每条答案可定位回原文的具体位置 |
| 拒答 | 检索结果不相关时明确说明，而不是硬答 |
| 知识沉淀 | 把有价值的结论存为知识条目（带溯源等级） |
| 插件扩展 | MCP 接入外部文档源（MDN、Context7 等） |

---

## 它不是什么

- **不是多租户 SaaS**。团队版是同一核心 + 不同存储后端 + 认证，不是第二个产品。
- **不是插件市场**。插件只服务自己用，不做生态、不做沙箱。
- **不是通用 agent 平台**。只做"在资料库中找答案"这一件事，不做代码编辑、不做任务编排。

---

## 关键设计决策（摘要）

1. **本地优先**。数据默认不出本机；"本地"也按服务器形态处理（localhost 服务 + 单一代码路径）。
2. **小核心 + 扩展点**。核心是稳定的契约；变动的是来源、格式和工具。
3. **插件协议用 MCP**，不自己发明。ingest 期的解析器用静态注册表，不需要热插拔。
4. **插件不贡献 UI**。插件产出结构化的渲染描述，核心用 6 种内置渲染器画。
5. **插件永远不直连数据库**，只通过 Host API。否则核心永远冻结不了。
6. **核心冻结前必须先跑通 3 个真实插件**。冻结太早比太晚危险。
7. **引用定位（locator）由解析器产出**，这一点在第一个解析器就要做对，事后补最贵。

完整理由见 [docs/architecture.md](docs/architecture.md)。

## 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | TypeScript | 全栈一套工具链 |
| 前端 | React + Vite | 主界面 + 6 个渲染器 |
| 服务端 | Node.js（独立包，可 headless） | 评测必须能在 CI 里无界面跑 |
| 桌面壳 | Tauri 2（最后做） | 性能、内存安全；sidecar 托管 Node 服务 |
| 存储 | SQLite + sqlite-vec | 零安装、单文件、整个库可带走 |
| LLM | OpenAI 兼容 API | 覆盖绝大多数 provider，用户自带 key |
| 扩展 | MCP（只依赖 tools） | 官方文档有现成 server（MDN、Context7） |

## 目录结构（规划）

```
Corpus/
├─ packages/
│  ├─ core/          # 数据类型、Host 接口、检索、生成链路
│  ├─ server/        # HTTP API、会话、文件、SQLite、迁移
│  ├─ web/           # 前端 + 6 个渲染器
│  └─ shell/         # Tauri（最后做）
├─ plugins/
│  ├─ mdn/           # MCP 配置示例
│  └─ db-explorer/
├─ evals/            # 30 条问答集 + 回归脚本
└─ docs/
```
